# 从定稿 HTML 导出可手动步进的视频 PowerPoint

## 从实际放映取得步骤

以教师认可的学生放映版为画面来源，登记入口、版本、画幅、原片及原声设置。在原播放器从第一页按“下一步”走到最后，记录每个学生能停下来看的状态。整页直接讲过只记一个状态。入页先提问、点击揭示答案、再点击揭示反馈回路的页面应产生三张 PPT。画面仍可显示原网页页码；导出顺序、原页与步号写进清单和备注。

清单中每步对应画面、口播、板书动作、起止时刻和原片选项。用放映顺序取得最新页码。为需要板书的课，从最终机制图向前拆，记录此刻应有的累计板书和本次增量；候答、原声和观察所占时间要留在相应步骤内。案例中的 21 页、42 步和 1200 秒是本课的核对值，其他课按自己的节奏计时。

### 生成清单

从技能包目录运行。脚本支持 UTF-8 JSON，以及文件内只有一个 `window.lesson = {…};` 且右侧为合法 JSON 的数据文件。其他引擎先从已运行的播放器导出相同字段的 JSON；由运行时生成的步骤要走真实点击顺序，包含教师会停留的入页状态。

```json
{"slides":[{"title":"小结","steps":[
  {"caption":"两端各发生什么变化？","note":"先留时间让学生判断。","board":"指左侧两处空白。","pace":"00:00–00:06　候答 6 秒"},
  {"caption":"展示结果","note":"请学生沿箭头解释。","board":"补上方向箭头。","seconds":12}
]}]}
```

```powershell
python -X utf8 scripts/lesson_steps.py lesson.json steps.json --expected-seconds 18
```

按可见页顺序提供 `slides`，每页的 `steps` 从入页状态开始。单状态页也可把时间、讲稿等字段直接放在页上。提供正数 `seconds` 或以连续起止时间开头的 `pace`；两者兼有时相互核对。`--expected-seconds` 可省略。脚本输出稳定的原页及步号标识（如 `03-2`）、PPT 页序、累计起止秒数，并保留当前步骤的 `original` 等媒体信息。用清单与播放器实际遍历结果核对；只有触发时创建的状态须由播放器提供。

## 录制学生所见的画面

- 固定本次画幅和投影分辨率，只录学生舞台，保留页码、章节、图注和 DOI。让导航工具退出画面，讲稿和板书只出现在教师端。先等字体、器官图、分子和嵌入资源就绪，再从该步骤的真实动作起点开始采集。会在入页立即启动的一次性动作，先布置采集，再触发进入或重播。需要上一页状态的播放器应按正常路径进入；支持深链的播放器可在验证两种起始画面一致后用深链。
- 从最终 HTML 获取封面、导入、病例回访等原片的静音、循环、裁切和叠字设置。保留原音轨；有叠字时可将实际 HTML 的透明前景合成到原片。原声步骤设 `original.sound=true`，若原播放器自定义音量，以 `original.volume` 记录 0 到 1 的值。把片长、留白和教师开口时机与讲稿核对。具体的原声、帧时间和完整解码检查沿用 `media-postproduction`。
- 离线模拟器使用课件随附的引擎、数据和网络视图。从基线施加同一扰动，录到讲稿引用的实际时点与读数；测一次断网重开和重播。HTML 保留交互，PPT 显示本次实算录像。用前、中、末帧核对传播方向和读数，避免录到尚在加载的 iframe。
- 把视频存为 `clips/<id>.mp4`，按舞台比例编码为方形像素 H.264；有原声的步骤保留音轨。将该步的正确入场画面存为 `posters/<id>.jpg`。有累计板书时，从同步的教师窗口获取 `boards/<id>.png`，待页码和步号都到位后再采集。

## 装配视频 PPT

以下工具需要 Windows 桌面版 PowerPoint 和可调用的 `ffprobe`。示例在项目工作目录运行，`$skill` 指向主技能包。传入已核准的步骤清单和素材目录，指定新的输出文件名。

```powershell
& "$skill/scripts/build_click_ppt.ps1" -Manifest ./steps.json -ClipDirectory ./clips -PosterDirectory ./posters -BoardDirectory ./boards -OutputPath ./比赛放映版.pptx
```

`-BoardDirectory` 可省略；传入时应包含每一步的累计板书图。默认 16∶9，其他画幅通过 `-WidthPoints` 和 `-HeightPoints` 指定。工具核对每段画幅、时长和声明的原声音轨，一步建一张并内嵌媒体。入页自动播放，整页点击或方向键由讲者推进，最后一步结束放映。讲稿、计时和板书文字进入同一张备注。

### 已复现连播停顿时使用兼容模式

在单独的目录中只放选中的无声动画，例如 `motion/05-1.gif`。从同一步 MP4 取帧，保留画布尺寸、时长、帧序和播放次数。首选数字、正文清晰的全色首帧作底；局部变化可作透明动图层，提交给装配工具时画布须恢复到完整舞台，动区仍在原坐标。原片、带音轨的片段以及讲课中要细读的复杂网络录像继续使用 MP4。再次调用装配工具，增加 `-MotionDirectory ./motion` 并给出另一个新的输出文件名。该模式仅在选中的步骤放置底图与动图，避免创建额外的视频播放器。

## 在最终文件里验收

1. 核对实际点击数、PPT 张数和总时长。抽查单步页、两次揭示的小结、一次性动作的交界和返回重播。确认投影的 DOI 可辨、二维码能解码、老师能在对应备注里读到当步稿件。
2. 对所有嵌入视频检查时长、音轨与完整解码。原声直拷时可比对音轨哈希；另在 PowerPoint 听病例原声，核对播放器音量与教师伴讲。逐步对照原 HTML 的首帧、动作终点和模型读数。
3. 在目标 PowerPoint 从第一张连续放到最后，检查后段视频的播放位置确实前进。局部抽查容易漏掉同一场放映累积后才发生的停播。记录宿主和复现位置；竞赛电脑可用时在该机复验。
4. 若复现连播问题，可将部分无声步骤改为由同一次录像生成的逐帧动画，静态底图用全色原画面，保留尺寸、帧序和时长；有声原片和关键演算优先用视频。对照转换帧、在原生放映窗口观察动作，并再次整场连播。需要全 MP4 且同机仍有问题时，可在自然章节交界提供验证过的上下场备用。根据实测选择交付版本。
